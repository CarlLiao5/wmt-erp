# 商品资料标准化读取收尾

## 范围

- 商品分析商品列表：只查询 `skus` 的独立 Item ID、名称、图片等字段，不再查询 `details`。注入旧数据源时的兼容转换保留。
- 退货产品中文名：读取 ALLSKU 独立 SKU、店铺、品名字段，保留租户缓存、店铺匹配及名称歧义规则。
- 公共成员权限：读取 ALLSKU 独立 SKU、店铺、负责人字段；原租户/店铺/SKU 匹配、授权期限及歧义拒绝逻辑不变。
- 经营目标初始化：读取 ALLSKU 独立业务字段，通过共享 `allSkuProductFields` 提取资料；目标公式、店铺匹配和定版流程不变。
- 独立字段存在时，空负责人/空标识不会回退到旧归档值。

本次只调整 API 读取，不改变 Worker 入库、表结构和统计口径。没有初始化、更新或删除 Doke 经营目标。

## 验证

- 测试新增标准字段优先、空值不恢复旧归档值两项，先红后绿。
- 9 个相关测试文件共 55 项通过，包括商品分析、成员权限、目标计算/授权、订单/退货接口及导出。
- API `tsc --noEmit` 及 `git diff --check` 通过。
- 独立代码审查未发现当前收尾修改的可执行问题。
- Doke 只读脚本 `scripts/verify-catalog-reader-cutover.ts`：318 行 ALLSKU 目标源资料新旧差异 0；673 个商品关联标识、名称和图片一致，返回不含 details；退货匹配 308 个中文名；4 个成员的可见店铺/SKU 集合新旧一致；目标写入 0。
- 此验证覆盖当前数据；不是全历史订单完整性审计，也没有发起外部 API 同步。
