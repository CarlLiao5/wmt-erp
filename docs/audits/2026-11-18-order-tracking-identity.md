# 订单物流身份统一

## 根因与规则

旧 ID 对 `carrierName` 对象整体 JSON 序列化后生成哈希。对象字段顺序、null 字段及 carrier/otherCarrier 表达变化会为同一条物流记录生成不同 ID；此前抽样的 71 个差异不能当成漏写记录。

新统一入口 `packages/db/src/normalization/order-tracking.ts`：身份为租户、店铺、采购订单号、行号、去首尾空白的物流单号与承运商文本。保留大小写，不猜测承运商别名。无物流单号时额外使用发货时间与 URL，避免合并不同未知包裹。已编号包裹的 URL、时间变更不生成新身份。

`normalizeOrderExtensions` 使用同一入口；首次、持续增量及原始响应回填经公共持久化路径生效。订单状态历史身份未改动，订单主表、订单行及销售金额未修改。
