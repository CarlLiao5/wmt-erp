# 订单扩展、库存健康与商品报告标准化实施计划

**Goal:** 将用户批准的三类数据标准化落入 Doke，更新首次与持续增量共用的 Worker 写入链路，并真实测试持续增量。

**Architecture:** 保留订单主表/行表及销售统计。新增订单扩展及金额/状态/追踪子表、库存健康及库龄快照、商品报告批次/商品快照/逐字段明细。用租户+店铺+业务身份实现幂等，迟到回填不覆盖新数据，集合更新在事务内执行。商品报告动态字段独立逐字段保存，常用数值/日期独立类型列。

**Constraints:** 当前工作区直接实施；只用 Doke；不更改订单取消排除规则、货件收发口径、权限、现有同步周期；不启动 ITS。

- [ ] 1. 核对真实响应字段，测试空值/0、毫秒日期、多状态/追踪、金额子项、重复/跨租户身份及过期写入。
- [ ] 2. 创建中文 COMMENT 迁移、Drizzle schema、标准化函数和批量事务仓库。
- [ ] 3. 订单原始页归档同事务写扩展；库存 health 每批次写快照/库龄桶；商品报告写批次、逐商品及字段明细。首次和持续增量使用同一业务 handler。
- [ ] 4. 库存页读取标准健康元数据；商品页读标准报告；订单详情仅为已授权订单行附加标准扩展字段，避免客户信息越权。
- [ ] 5. 执行 Doke 迁移及历史回填；商品历史仅能恢复现有 details 的当前一版，明确来源，不伪造已丢失历史。
- [ ] 6. 运行相关测试、API/Worker/DB 类型检查、真实 DB 幂等/回填保护验证；重启服务；触发真实持续增量并核对写入和页面兼容性。
