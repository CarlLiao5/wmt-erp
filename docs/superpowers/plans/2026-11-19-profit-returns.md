# 月度利润卖家退货调整实施计划

用户已确认当前目录实施；不改同步，不写业务数据库数据，不用 Docker。

## 已确认口径
按太平洋时间退货月份统计 Seller / Seller Keep-It 的已退款退货；WFS、未知、未完成另计数量。全部不可售、残值零。原销售成本保留，不再扣采购/头程/ITS。净扣减=商品退款+实际额外退货费用-佣金返还-实际赔付。佣金优先实际返还、原订单实际佣金按数量、SKU平均佣金率；来源与缺失单列，实际替代预估。包含跨月、部分退货。提供退货明细与Excel。

## 文件与执行
1. 新建 profit-returns.test.ts：先证明优先级、数量分摊、跨月、不重复计费、责任和状态过滤、缺失/零值、去重、空销售月退货的测试失败。
2. 新建 profit-returns.ts：纯核算函数与标准化数据库批量读取；所有查询租户隔离，按店铺/订单/SKU匹配。复用 recon_transactions，避免再次解析大 JSON。
3. 修改 profit.ts：并行加载退货调整，返回独立 returns 对象和 adjustedProfit，保留原 profit。无本月销售也核算历史订单退货。同一缓存结果支持 XLSX 导出。
4. 修改 ProfitPage.ts/CSS：调整后利润与退货统计、搜索/分页明细、费用来源和导出。明确缺失及待核对，不把缺失费用当完整净利。
5. 验证聚焦测试、API/web tsc、web build；Doke只读真实月份验证汇总与导出；重启 API、验证 HTTP 权限和页面。

## 分摊与限制
Recon没有独立退货行关联键时，账单按同店铺/订单/SKU全部已退款退货分摊，包含其他责任和其他月份，避免重复使用整笔账单。显示分摊来源。无法关联原订单或费用字段缺失时标记。退货商品成本按现有最新成本口径展示，仅为参考不再扣。
