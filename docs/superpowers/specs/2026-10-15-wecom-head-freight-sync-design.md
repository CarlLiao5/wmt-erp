# 企微智能文档头程综合同步设计

## 目标

增加一个租户级的企业微信智能文档同步能力，将头程在途智能文档的每一行完整写入当前 ERP。智能文档中的“店铺名称”只用于尝试关联 ERP 店铺，不是落库条件：匹配成功写入 `store_id`，匹配失败仍完整保存原始店铺名称和其他字段。

## 范围与约束

- 同步入口复用现有 API → BullMQ → Worker 链路。
- Sync Status 只增加一个综合按钮“同步头程在途”，不按店铺增加按钮。
- Bot 配置按租户保存一次，不为每个店铺增加 Bot 配置。
- 不新增 WFS 或头程页面；结果通过同步任务状态和现有运维信息查看。
- 不使用脚本中暴露的旧 Bot Key；正式接入使用新的配置值，密钥不写源码、日志或提交记录。
- 智能文档原始 MCP 响应写入 `raw_payloads`，标准化字段写入 ERP 在途表。
- 重复同步使用幂等键更新同一记录，不产生重复数据。

## 数据与店铺关联

在途表保存租户、可空的 `store_id`、智能文档中的原始店铺名称、业务字段、原始载荷引用、同步批次和幂等键。店铺匹配只在写入时尝试，按租户内店铺名称匹配；没有匹配结果时不得抛出批次异常，也不得丢弃该行。同步结果统计成功写入行数、未匹配行数和未匹配店铺名称。

脚本现有业务关联优先级保持不变：合同编号、SKU、WFS 货件号用于补充或更新在途记录；空占位行跳过，非空字段更新不能被空值覆盖。

## 配置与接口

- 新增租户级智能文档 Bot 配置的读取/保存接口，返回时脱敏。
- 新增 `head-freight` 同步资源到 API 白名单和 Worker 分发。
- 同步任务载荷包含租户、窗口、批次和文档配置引用，不把 Bot 密钥放进队列日志。
- Worker 使用 MCP JSON-RPC 初始化会话、分页读取 `smartsheet_records_list`，逐页持久化原始响应并标准化写入在途表。

## 错误处理

- MCP 认证、网络、分页协议或数据库错误属于批次级失败，并保留已写入的原始响应与可重试状态。
- 店铺不匹配属于行级信息，不影响其他行；任务可以成功完成，并在结果中报告未匹配信息。
- 空文档或只有占位行时任务成功但写入数量为零。

## 验收标准

1. 含有已匹配和未匹配店铺的文档，所有有效行均在 ERP 可查询；匹配行有 `store_id`，未匹配行 `store_id` 为空且原店铺名称保留。
2. 一条店铺匹配失败不会阻止后续页或后续记录写入。
3. 同一批次重复执行不会增加重复在途记录。
4. 原始 MCP 页响应和标准化行都落库，任务结果包含未匹配数量与名称。
5. 租户之间不能读取或覆盖对方的 Bot 配置、原始数据和在途数据。
6. Sync Status 只显示一个综合同步按钮，前端不直接调用企微或 Walmart。
