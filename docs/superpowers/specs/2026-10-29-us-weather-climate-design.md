# 美国天气与气候监控设计

## 目标

新增“美国天气气候”页面，覆盖美国本土 48 州，展示当前天气、短期天气预报、气候历史和 NOAA 气候展望。所有外部请求由服务端发起，前端只读取 ERP API，避免暴露 NOAA 凭证并统一处理缓存、限流和失败重试。

## 数据范围

### NWS API

- `/points/{lat},{lon}`：将州代表坐标映射到预报网格和气象站。
- `/gridpoints/{wfo}/{x},{y}/forecast`：未来 7 天预报。
- `/gridpoints/{wfo}/{x},{y}/forecast/hourly`：逐小时温度和降水概率。
- `/stations/{stationId}/observations/latest`：当前观测。
- `/alerts/active?area={state}`：当前警报。

### NOAA 气候数据

- NCEI 日/月历史数据：月平均温度、最高/最低温和降水量。
- CPC 气候展望：6–10 天、8–14 天、月度和季节性温度/降水概率。
- 气候展望使用“高于/接近/低于历史平均”的概率表达，不伪装成确定温度。

## 48 州覆盖

建立固定的州配置表，包含州代码、名称、代表城市、纬度、经度和默认气象站。阿拉斯加、夏威夷、波多黎各和其他领地不在本期范围内。代表坐标用于州级概览，详情可进一步切换到气象站。

## 页面交互

- 导航新增“美国天气气候”。
- 州卡片显示当前温度、体感温度、天气状况、湿度、风速、警报数量和更新时间。
- 支持州名/城市搜索、州筛选和温度/降水排序。
- 点击州卡片打开详情面板：7 天预报、逐小时温度曲线、降水趋势、历史气候均值对比、CPC 气候展望。
- 图表悬停显示具体日期、数值、单位和数据源；无数据明确显示“暂无数据”。
- 页面展示数据更新时间、缓存状态和接口异常提示。

## 缓存与限流

- Redis 缓存：当前观测 10 分钟、短期预报 30 分钟、警报 5 分钟、历史气候和 CPC 展望 24 小时。
- 外部请求进入独立天气队列，默认串行并设置最小请求间隔，避免一次加载 48 州造成突发流量。
- 处理 HTTP 429、5xx、超时和响应格式错误，采用有限次数的指数退避；失败不覆盖已有缓存。
- NWS 请求带统一 User-Agent；NOAA token 仅保存在服务端加密配置中，不进入前端、日志或仓库。

## API 边界

- `GET /api/weather/states`：返回 48 州概览，支持搜索、排序和分页。
- `GET /api/weather/states/:stateCode`：返回某州当前天气、预报、历史气候和展望。
- `GET /api/weather/health`：返回缓存、队列和外部数据源的脱敏状态。
- API 按当前租户鉴权；天气为公共数据，不按 SKU 或店铺过滤。

## 数据落库

使用独立表保存规范化快照和请求元数据，至少包括州代码、数据源、观测/预报时间、指标、单位、原始更新时间、缓存过期时间和请求状态。原始响应可按现有 raw payload 约定保存，禁止保存 token。

## 验收标准

1. 48 个州均可在概览列表中显示，单州失败不影响其他州。
2. 详情可看到未来 7 天和逐小时预测；气候区域能区分历史统计与概率展望。
3. 重复刷新命中缓存，不重复请求外部接口；429 时不会无限重试。
4. 前端和 API 不出现 NOAA token 或完整请求头。
5. TypeScript 检查、API 路由测试、限流/缓存测试和页面渲染测试通过。
